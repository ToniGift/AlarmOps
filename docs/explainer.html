AlarmOps

Before anyone changes a safety alarm, this system measures what the change would do, and a person approves only the final step.

This is a simulation. It uses made-up sensor readings. It is not connected to any real plant or equipment.

The problem

In a factory, an alarm limit is the number at which the control system warns an operator. For example: "tell someone if the tank is more than 80% full." Over the years people edit these numbers. If a limit is loosened by mistake, a real problem can happen with no warning at all. If it is tightened too far, operators drown in false alarms and start ignoring them. Today these edits are usually checked by eye, and nobody measures what they really do.

What AlarmOps does

Every proposed change goes through nine automatic steps. Only one needs a human.

  1. Plan
    Check the change is well-formed.
  2. Review
    Replay simulated faults on the old and new limits, and compare.
  3. Test
    Run the automatic tests.
  4. Security
    Scan for passwords and keys saved in the code.
  5. Compliance
    Write the change record and a parts list (SBOM).
  6. Deploy to staging
    Release to a practice environment.
  7. Validate
    Check the practice release works.
  8. Human approval
    A person decides. This is the only manual step.
  9. Monitor
    Watch alarm counts after release and open an issue if they drift.

What this is not

  • It is a simulation, not a product for real plants.
  • The mapping to industry standards (ISA-18.2, IEC 62443) is a reference, not a certification.
  • The pass/fail thresholds are choices for this demo, not an industry standard.
