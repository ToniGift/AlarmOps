01 / The problem

A loosened limit fails silently

In a factory, an alarm limit is the number at which the control system warns an operator. Over the years people edit these numbers.

Loosen a limit by mistake and a real problem can happen with no warning at all. Tighten it too far and operators drown in false alarms and start ignoring them.

Today these edits are mostly checked by eye. Nobody measures what they really do, and nobody watches the alarm rate afterwards.

Words used on this page

Alarm limit
The number at which the control system warns an operator, such as a tank being 80% full.
Fault
Something going wrong in the process: a sudden spike, a slow drift, or a sensor stuck on one value.
Detection rate
Of the faults we hid in the data, how many the alarms noticed.
False alarm
An alarm that sounds when nothing is wrong. Too many and operators stop listening.
Deadband and delay
Two settings that stop alarms from flickering: how far the value must recover, and how many readings in a row must break the limit.
Gate
The pass or fail rule. A change that loses too much detection is blocked.

02 / How it works

Nine automatic steps, one human

Every proposed change runs this line. It stops at the first step that fails. Only the approval is manual.

  1. PlanCheck the change is well-formed.
  2. ReviewReplay hidden faults on the old and new limits. Compare.
  3. TestRun the automatic tests.
  4. SecurityScan for passwords and keys saved in the code.
  5. ComplianceWrite the change record and a parts list.
  6. StagingRelease to a practice environment.
  7. ValidateCheck the practice release works.
  8. ApprovalThe one manual step. A named person says yes.
  9. MonitorWatch alarm counts after release. Open an issue if they drift.

03 / After release

The monitor screen

Releasing a change is not the end. The monitor counts alarms per hour after the release and compares the recent hours with the quiet period before. If the rate climbs past the drift limit, it raises an issue with a diagnosis.

How the pass or fail is decided

A change passes if it keeps at least 90.0% detection, loses no more than 5.0% compared with the current rules, causes at most 3 false alarms, and adds at most 2. A fault counts as noticed when an alarm for its tag starts between the fault's start and 20 readings after its end. These thresholds are choices for this demo, not an industry standard. 05 / What this is not

Honest limits

A simulationThe sensor data is made up and the deployment is simulated. It is not connected to any real plant or equipment.
Not a certificationThe mapping to ISA-18.2 and IEC 62443 in each change record is a reference mapping. It is not a certificate or a compliance claim.
Demo thresholdsThe pass and fail numbers are policy choices made for this demo, not an industry standard.
